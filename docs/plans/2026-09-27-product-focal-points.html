Product focal points — every SKU, every image

2026-09-27 · branch fix/lh-imagery-bindings · founder direction: the styling pieces (e.g. the Love Hurts script hoodie) stay for branding; the item for sale must be the focal point.

1. Goal and rule

On every selling surface — collection pages, product cards, product pages, lookbooks, feeds — the first thing the eye lands on is the SKU being sold. Styled context (other garments, the room, the model) stays, but second.

  • First view: the on-model image cropped to the item for sale (its focus box ).
  • Second: real photographs and packshots (back, flat, detail).
  • Context: the full styled frame, shown small ("In the room") or as an alternate view.
  • Never upscale a crop past 1.75× its native pixels. Where the crop is too small, the fix is a better source image, not a bigger display.

2. Where the focus box lives

The registry owns image bindings, so it owns the box. One new optional field per image binding:

products[sku].images[role].focus = { "x": 0.30, "y": 0.46, "w": 0.38, "h": 0.50, "checked": "2026-09-27" }

  • Fractions of the frame, so the box survives format siblings (webp/avif/png of the same image) and resizing.
  • Written through a new registry update function update_image_focus(sku, role, box) beside update_catalog_fields in skyyrose/core/product_registry.py : same lock, same validation style (0 ≤ x, y; x + w ≤ 1; y + h ≤ 1; w, h > 0).
  • Projected by get_product() , data/sot-images.json ( python -m skyyrose.core.sot_images ) and the V2 presentation registry, so PHP and JS consumers read it without a second list.
  • If an image is re-bound, its box is dropped in the same write — a box describes one image, never a role.

3. How a box is verified

  • Each box is checked by cropping the actual image to it and looking at the crop: the whole item for sale is inside, and no other product competes. This check can fail, and a failed crop is re-drawn, not accepted.
  • Test (new, in tests/ ): every published SKU's front binding has a focus box; every box is inside the frame; the box's native pixel width is reported, and a crop under 400 px wide is listed as low-res , not hidden.
