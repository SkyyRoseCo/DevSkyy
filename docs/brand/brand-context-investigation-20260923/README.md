# SkyyRose brand source investigation and context proposal

**Review package · 2026-09-23 · not a replacement canonical system**

SkyyRose has identifiable founder-grounded brand truth, but no single existing file safely represents the entire brand. Authority is divided by field. Current context generators, historical briefs, collection worlds and deployed experiences contain material conflicts. Following the owner's direction, staging is the primary reference for current visual expression; production serves as a comparison and drift check.

Start with [the investigation report](REPORT.md). It contains the source hierarchy, conflict register, invariant review, creative saturation register, freedom model, drift map and adoption decisions. [context-manifest.json](context-manifest.json) is the proposed machine-readable assembly contract. [evidence.json](evidence.json) provides 44 indexed evidence records. [validation.json](validation.json) records the checks and coverage limits. [source-snapshot.json](source-snapshot.json) hashes inspected source files so future readers can detect changes.

The package preserves existing source ownership. Product facts resolve through `skyyrose.core.product.get_product`; typography and collection identity keep their existing owners. Proposed classifications and freedom levels remain proposals. They do not authorize new creative usage, spending, publication, deployment, migration, or rewriting founder decisions.

This investigation added only this directory. Existing canonical assets and application code were not edited. No commit, push, merge, deployment or publication was performed.

The supplied attachment ends mid-example after “VISUAL GRAMMAR.” The completed requirements before that truncation were used; the resolution design is explicitly a proposal, not a reconstruction of unseen instructions.
