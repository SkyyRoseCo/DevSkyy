# Creative OS v1: bounded local editorial route

The existing Creative Operations Hub now exposes `run_editorial(adapter, directions, root=..., output_dir=..., grant=...)` through `skyyrose.elite_studio.creative.runner`. A brand adapter resolves a compact execution/audit pair and bound source. The coordinator persists the pair, requires an independently supplied local-action grant, applies a nine-render / three-per-direction job allowance, and calls the deterministic local compositor. It never reads a grant from creative brief fields.

Only image / editorial_still / SOURCE_COMPOSITE execution is implemented. Film, 3D and interactive work remain planning-only. Unsupported routes raise a capability limitation. Market experiment contracts can record prospective design, but this route never launches traffic or claims market results.

## Invocation

From the reconstructed repository using its installed Python dependencies (Pillow, NumPy, Pydantic):

```sh
PYTHONPATH=. python scripts/run_creative_os_pilot.py --output .artifacts/creative-os-v1 --revision 3 --authorize-local
```

The switch is an explicit trusted operator invocation under an existing grant, not an approval generated by the model or by a brief. Do not run it without an applicable owner request. For this task the owner adopted the revised handoff and said “start implementing.” No provider, upload, spending, messaging, commit or publication permission follows.

The script builds fictional local material environments, resolves br-001 from current product authority, and binds its reviewed front-facing packshot. Revision 1/2 retain the recorded experimental silhouette masks for reproducibility; they failed complete silhouette coverage and are not recommended. Revision 3 preserves the complete source photograph as an intentional opaque photographic plate. It does not claim seamless extraction. Actual production used nine renders; its authority ledger is exhausted. Do not reset/remove that ledger or select another output folder to evade the limit.

The fixed ledger is under `.artifacts/creative-os-authority/`, keyed by job/source/approval identity independently of the chosen destination. New directories do not reset an existing grant. Local callers/filesystem owners remain the trust boundary; this is not a remotely authenticated multi-user permission service.

## Verification and review

`verify_composite` independently compares the PNG against expected transformed source/background pixels, checks immutable input and output identities, and rejects competing color-profile declarations. It compares opaque interiors and boundaries separately, with fixed zero-error lossless tolerances. Source and mask completeness require visual inspection; pixel equality alone cannot detect omitted garment regions.

`assess_editorial_review` requires the brand adapter to resolve current authority again and rejects a changed job contract before combining fresh technical verification with artifact-bound, attributed visual evidence. Every required visible-fidelity criterion needs PASS plus evidence. Missing checks block fidelity. Creative judgments are RECOMMENDED/REVISE/REJECT; this interface cannot manufacture owner approval. The review result records product-fidelity completion separately from creative revision needs.

For already-produced files, an explicit hash-bound `producer_implementation` source snapshot allows current verification of historical request identity. Old code is read only as inert bytes; it is never imported or executed. The assessment identifies old producer and current verifier separately. This revalidates existing output, consumes no render attempt, and never overwrites the original receipt.

Each brand adapter resolves afresh. Existing run directories reject changed compact/audit records; source/rule changes require a newly reviewed context. `verify_context_link` checks stored record identity and availability; by itself it does not assert freshness against external canonical sources. The audit digest links records, not approval. Source visual-review records are matched to SKU, role, observed view, digest, reviewer and method; they are evidence, not cryptographically authenticated reviewer identity.
