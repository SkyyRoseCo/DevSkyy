CLO3D / pattern-based garment pipeline — evaluation

2026-09-17 · item 5 of the founder 3D brief · decision document, nothing purchased or installed

Verdict

Yes, sewing patterns can be built — but not from anything currently in the repo. Pattern drafting needs garment measurements, and 0 of 33 products carry one: every garment.sizing_references.garment_size_chart in the product registry is null , and that same record states the rule "Use founder specifications and actual product flatlays; no inferred garment measurements." So the one missing input is a flat-measure spec taken off the real samples. Inventing it is not an option, and estimating it from photos is the same thing wearing a hat.

What this would replace, and what it would not

Today's 33 web GLBs come from Meshy: one image → one mesh, one material, one baked texture atlas. That is why two limits exist that no amount of material tuning fixes:

  • Inferred geometry. A back that no photo showed is a guess. This is the recurring wrong-garment defect class (bug-096).
  • Incoherent UVs. The atlas is fragmented AI islands, so there is no fabric grain direction. That is exactly why KHR_materials_anisotropy is off by default in the web build: anisotropy is defined in tangent space, which an AI atlas does not align to the weave. A pattern-based garment has UVs that follow the grain line, so anisotropy becomes physically meaningful on satin and nylon for the first time.

What does not change: CLO3D does not export the glTF sheen or clearcoat extensions, so the glb_materials sheen patch and the gltfpack + web_gate steps stay in the pipeline regardless of where the geometry comes from. The work built for items 1 and 2 is not thrown away by adopting CLO.

Proposed path (cheapest first)

  1. Five base blocks cover most of the line: fleece crew/hoodie, cotton tee, jogger, mesh basketball short, knit jersey. That is 26 of 33 products. The outliers are the Bomber Sherpa (two-layer satin placket + storm flap), the Love Hurts Bomber (raglan + rib banding), the Windbreaker Set, the Signature Beanie and The Fannie — those are individual drafts, not block variants.
  2. Draft in a free tool first. Seamly2D drafts parametrically and exports DXF-AAMA, which is what CLO and Marvelous import. That lets the block work happen at $0 before any subscription is bought.
  3. Simulate in one paid tool, on one product, as a pilot. Judge it side by side against the real front photo before buying a year.
  4. Run the pilot GLB through the existing web build ( scripts/build_web_glbs.py ) so it is measured against the same 3MB budget and gate as the Meshy set, then compare the two in the same viewer.

On export format alone CLO3D is the fit: GLB out of the box is the format the storefront consumes. Marvelous is cheaper and better at cloth realism but would need an OBJ/FBX → GLB conversion step, and this repo already has a Marvelous CLI harness whose own notes record that no command-line session exists as of MD 12 — meaning neither tool becomes an unattended pipeline stage. This stays designer-in-the-loop work.

Decision points for the founder

  • Measurements. Will you flat-measure one sample per silhouette? Nothing downstream can start without it.
  • Pilot scope. One product end to end (recommended: a cotton tee — simplest block, and its Meshy GLB is already the smallest at 0.98MB, so the comparison is clean) before any subscription decision.
  • Purchase. A CLO3D or Marvelous subscription is real money and needs an explicit go — it is not covered by any approval in this session.
