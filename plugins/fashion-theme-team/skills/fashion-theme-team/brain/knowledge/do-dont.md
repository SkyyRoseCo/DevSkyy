# Fashion Theme Do and Don't

> **SKYYROSE LLC · FASHION THEME BRAIN**  
> *SkyyRose*

| Do | Don't |
| --- | --- |
| Derive a recognizable grammar from approved brand, product and audience evidence. | Start with black, gold, serif type and call it luxury. |
| Let garment scale, texture, silhouette and construction drive composition. | Use stock lifestyle media or oversized slogans to hide weak product content. |
| Give each route one primary customer job and conversion purpose. | Repeat a hero, logo cloud and product grid on every page. |
| Use real sections only when data, states and ownership exist. | Draw wishlist, reviews, loyalty, personalization or filters that are not wired. |
| Show verified size, fit, material, delivery and returns information near the decision. | Bury purchase-critical facts beneath cinematic effects. |
| Treat mobile as a deliberate transformation with preserved product truth. | Collapse desktop into a long narrow stack or hide essential controls. |
| Make motion explain hierarchy, continuity or product detail and provide reduced-motion behavior. | Add parallax, marquees, scroll hijacking or cursor effects as generic decoration. |
| Use approved scarcity and inventory language. | Create fake countdowns, viewer counts, urgency, reviews or stock warnings. |
| Prefer hooks, global styles and stable extension points. | Override every WooCommerce template or target private block internals. |
| Render HTML fixtures and validate matching JSON contracts. | Accept prose-only visual claims or JSON that no reviewer has rendered. |
| Label evidence, inference and experiments. | Say a pattern “will convert” because another brand uses it. |
| Test content extremes, missing media, unavailable stock and failures. | Certify a polished happy-path screenshot as a complete commerce theme. |

## Generic-output red flags

- Interchangeable aspirational copy.
- Centered logo, full-screen hero, serif display and sparse grid with no brand-specific device.
- Every section uses identical card radius, shadow, spacing and reveal animation.
- Product grids without useful product-card decisions.
- Decorative 3D/WebGL before core commerce is complete.
- Lookbook that cannot identify or reach products.
- Mobile sticky actions that obscure content or bypass variation validation.
- Dark mode that treats contrast, media art direction and checkout as afterthoughts.
- A design system documented as tokens but not adopted in rendered routes.

## Adversarial questions

1. With the logo removed, what three devices still identify this brand?
2. What shopper uncertainty does each section resolve?
3. Which feature disappears if its real data or service is unavailable?
4. Can a keyboard and screen-reader user complete the same purchase and recovery paths?
5. What happens with a long title, one image, no reviews, out-of-stock variation and payment failure?
6. Which claim requires a current source, and which requires a local executable test?
7. Which conversion claim is actually an experiment?
